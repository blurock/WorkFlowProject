# Phase 1 Specification: Replacing GDBM with Cloud Firestore as Persistent Storage

## Overview

This specification details Phase 1 of introducing Cloud Firestore as the persistent storage engine for the REACT C backend (`REACTCLOUD/dbase`), replacing GNU Database Manager (`gdbm`) binary file storage (`.dbf`).

Currently, REACT manages 7 persistent databases:
1. `BensonTables`
2. `ChemkinThermo`
3. `Molecules`
4. `ReactionPatterns`
5. `Reactions`
6. `RxnMechanism`
7. `SubStructures`

### Phase 1 Execution Principles
1. **Parallel Execution / Coexistence**: GDBM will **not** be phased out immediately in Phase 1. Database operations will run in parallel: existing GDBM binary file operations remain active while Firestore JSON record operations are added.
2. **Structured JSON Objects**: Records are serialized into structured JSON objects using the automatically generated REACT `WriteJSON<Structure>` / `cJSON` functions (from `createstructures` templates).
3. **Orchestrator Local HTTP/IPC Bridge**: The C backend communicates with Firestore through the Node.js Orchestrator (`server.js`) local API using Firebase Admin SDK.

## 2. Firestore Hierarchy & Document Schema

### Firestore Collection Path
```
users/
  {uid}/
    databases/
      {dbName}/               (e.g. Molecules, Reactions, BensonTables)
        records/
          {keyId}/            (e.g. MOL-1001, RXN-502)
```

## 3. C Backend Refactoring (`REACTCLOUD/standard/dbase.h` & `REACTCLOUD/dbase/datum.c`)

### DataBaseInformation Extensions

In `dbase.h`, `DataBaseInformation` is extended with JSON conversion function pointers:

```c
typedef cJSON *(*WriteJSONConversionFunc)(VOID element);
typedef INT (*ReadJSONConversionFunc)(VOID element, cJSON *json);

struct DataBaseInformation_ {
    /* Existing fields */
    INT ID;
    CHAR *Name;
    /* ... */
    INT (*WriteConversion)(VOID element, DbaseLinkedList *link);
    INT (*ReadConversion)(VOID element, DbaseLinkedList *link);

    /* Phase 1 JSON Extensions */
    WriteJSONConversionFunc WriteJSONConversion;
    ReadJSONConversionFunc ReadJSONConversion;
};
```

### Dual-Write Logic in `StoreElement` (`datum.c`)

When an element is stored via `StoreElement`:

```c
extern INT StoreElement(VOID element,
			DbaseKeyword *keyword,
			INT flag,
			DataBaseInformation *info)
{
    /* 1. Existing GDBM Store (Parallel Execution) */
    DbaseLinkedList *firstlink = AllocateDbaseLinkedList;
    CreateDbaseLinkedList(firstlink, keyword->ID, keyword->Name, LINKED_SIZE, 0, 0, 0, 0);
    (*info->WriteConversion)(element, firstlink);
    INT gdbm_ret = WriteGenericElement(firstlink, keyword, flag, info);
    FreeDbaseLinkedList(firstlink);
    Free(firstlink);

    /* 2. Phase 1 Firestore Store (JSON Object via Orchestrator) */
    if (info->WriteJSONConversion != NULL) {
        cJSON *jsonObj = (*info->WriteJSONConversion)(element);
        if (jsonObj != NULL) {
            StoreElementToFirestore(keyword, jsonObj, info);
            cJSON_Delete(jsonObj);
        }
    }

    return gdbm_ret;
}
```

## 4. Orchestrator Proxy Endpoint (`server.js`)

The Node.js Orchestrator provides endpoint handlers:

### `POST /api/db/store`
- Receives JSON payload: `{ uid, dbName, key, keyId, jsonObject }`
- Stores or updates document at `users/{uid}/databases/{dbName}/records/{key}`.

### `POST /api/db/fetch`
- Receives payload: `{ uid, dbName, key }`
- Returns Firestore document data object.

## 5. Implementation Roadmap

1. **Step 1**: Add `WriteJSONConversion` / `ReadJSONConversion` fields to `DataBaseInformation` in `dbase.h`.
2. **Step 2**: Implement `StoreElementToFirestore` and `FetchElementFromFirestore` helper functions in `REACTCLOUD/dbase/datum.c` (using cJSON & local HTTP IPC).
3. **Step 3**: Add `/api/db/store` and `/api/db/fetch` routes to `REACTCLOUD/orchestrator/server.js`.
4. **Step 4**: Test and verify parallel writing to GDBM files and Cloud Firestore.
