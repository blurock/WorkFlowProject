Transaction Sequences

Orchestrating multi-step chemical operations and dynamic user-input boundaries through integrated cloud pipelines and semantic interfaces.

Overview

In scientific data management, inserting a target data record (e.g., interpreting Benson rules for a specific molecule) is rarely a single, isolated step. It typically depends on a chain of prerequisite transactions—such as uploading a chemical structure file, extracting the molecule definition, and calculating intermediate parameters.

The Transaction Sequence feature coordinates this dependency resolution automatically. It ensures that all prerequisites are satisfied before the target transaction is executed. When a step requires human curation, the pipeline pauses, delegates control to the user interface, and resumes dynamically.

Sequence Lifecycle

Phase 1

Prerequisite Calculation

When a workflow is started with the transactionsequence type, the parent workflow queries the backend database catalog service to retrieve the ordered list of dependencies required for the target transaction event.

Phase 2

Existence Checking & Iteration

The workflow loops through each transaction in the computed dependency list. For each transaction, it queries Firestore to see if that record has already been computed and stored. If it has, the step is skipped; if not, the workflow triggers the sub-workflow pipeline.

Phase 3

Human-in-the-Loop Interruption

If a transaction has no database record, the sub-workflow registers a callback webhook in Google Cloud Workflows, saves the callback URL and task state to the session document in Firestore, and suspends execution.

Phase 4

Resume and Progression

The frontend detects the suspended state, renders the required scientific inputs, and prompts the user. Once the user submits, the frontend fires a POST to the callback webhook, waking up the workflow to proceed to the next iteration.
