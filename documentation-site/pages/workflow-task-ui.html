Human-in-the-Loop Workflows

Architecting an Angular and Firestore driven hub for pausing algorithmic workflows and injecting human interaction dynamically.

Architecture Overview

When processing scientific transactions in the BackgroundTransactionController, automated jobs occasionally hit a boundary requiring manual user curation, correction, or data entry. This sub-system seamlessly pauses backend processing, queues the action in SessionData, and delegates the task to the frontend via a unified router portal.

1. Routing and State Management

The frontend maps the unified route /workflow-task/:uid/:sessionId to the WorkflowTaskComponent. This allows dynamic resolution of any task state solely through the URL without needing specialized views for every edge case.

2. Security & Data Integrity

The active logged-in user is validated strictly against the uid parameter. The component then fetches the raw SessionData using the ReadSessionDataService endpoint. If the user does not possess authorization, the UI politely defaults to an isolated error state.

3. Dynamic Form Injection via NgSwitch

Once extracted, the backend queue structure identifies what sort of data it demands (e.g., dataset:ActivityRepositoryInitialReadLocalFile). The component leverages Angular's *ngSwitch to pipe the activityData into the predefined app-dynamic-primitive hierarchy, querying the Ontology for the layout map and rendering the targeted scientific data form automatically.

4. Form Re-Sumission and Resume

When completion tasks conclude, the Angular component updates the specific data block via UpdateSessionDataService. Crucially, the web portal fires an HTTP Ping to the embedded resumeEndpoint registered inside the Session Data payload, awaking the waiting background transaction thread to resume the data pipeline.
